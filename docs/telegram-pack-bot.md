# Локальный бот для публикации пака

## Версия 2: дозагрузка и живой прогресс

Запуск: `scripts/start-telegram-bot-v2.cmd`. Текущий процесс V1 не обновляется
на ходу: дождись завершения или остановки его задания и запускай V2 после
выхода из V1. Два процесса одного бота одновременно запускать не нужно.
Токен, владелец и ранее загруженные файлы берутся из тех же `.env` и локального
кэша. V2 поддерживает существующую историю V1.

- `/newpack` — создание набора эмодзи, стикеров или обоих.
- `/add` — пришли ссылку существующего набора и нажми «Добавить».
  Бот сверит архив с реальным набором, добавит только отсутствующие файлы,
  существующие элементы сохранит. Можно передавать полный обновлённый архив:
  повторно загружать старые файлы не требуется.
- `/packs` — ссылки на наборы, известные локальной истории этого бота.
- Архив перечитывается перед `/newpack` и `/add`, поэтому для новых эмодзи
  достаточно пересобрать `exports/blue-pack.zip` без перезапуска V2.
- Вместо потока сообщений бот редактирует одно сообщение прогресса раз в
  5 секунд. В нём текущий файл, прошедшее время, ожидание Telegram и итоговые ссылки.
  `/status` остаётся запасным способом проверить состояние.

Дозагрузка доступна для наборов, созданных **этим же ботом для твоего аккаунта**,
с сохранённой локальной историей. Это ограничение
[метода addStickerToSet](https://core.telegram.org/bots/api#addstickertoset).
Если данные файла изменились, его новый SHA-256 рассматривается как новый элемент;
автоматической замены или удаления существующих эмодзи нет.
Проверка учитывает фактическое содержимое Telegram, включая удаление вручную и
успешное добавление с потерянным ответом сервера. `file_unique_id` позволяет
узнавать файлы даже при смене `file_id`.

Очередь последовательная. Базовая пауза между запросами загрузки и изменения
наборов — 8 секунд (`PACK_REQUEST_INTERVAL` в `.env`, минимум 2 секунды).
При `429` бот полностью выдерживает `retry_after`, удваивает интервал (до 120 с)
и сохраняет ожидание на диске: перезапуск не обнуляет лимит. После десяти
успешных запросов интервал постепенно уменьшается к базовому. Отдельная очередь
сообщений не даёт запросам прогресса блокировать загрузку. Сетевые ошибки и 5xx
повторяются ограниченно, с увеличением паузы; создание набора с неопределённым
результатом проверяется при продолжении, без слепого повторного создания.
Сервер всё равно может вернуть `429`: конкретные лимиты загрузки Telegram
не публикует, поэтому обещать полное отсутствие ограничений нельзя.

V2 принимает архивы до 200 TGS. При создании первые 50 добавляются одним запросом,
остальные — очередью. Лимиты текущего Bot API: 200 эмодзи или 120 обычных стикеров
в наборе; вместимость проверяется перед дозагрузкой.

Проверка без сети и токена:

```powershell
.venv/Scripts/python.exe scripts/test_telegram_pack_bot.py
.venv/Scripts/python.exe scripts/test_telegram_pack_bot_v2.py
```

## Первоначальная настройка

Python 3.10+, без установки библиотек. Скрипт запускается на твоём компьютере,
читает готовый ZIP и общается с официальным Telegram Bot API.

1. Создай бота в [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Скопируй `.env.example` в `.env` в корне проекта и вставь токен в
   `TELEGRAM_BOT_TOKEN=...`. Если `.env` уже есть, добавь эту строку туда.
3. Запусти двойным кликом `scripts/start-telegram-bot.cmd` или командой:

   ```powershell
   .venv/Scripts/python.exe scripts/telegram-pack-bot.py
   ```

4. Консоль покажет имя бота и одноразовый код. В личном чате с ботом отправь
   `/start КОД`. После привязки бот доступен только твоему аккаунту.
   Можно заранее задать свой числовой `TELEGRAM_OWNER_ID` в `.env`.
5. Выбери **Эмодзи**, **Стикерпак** или **Оба**, введи название и короткое имя ссылки.
   Бот покажет итоговые ссылки. Нажми **Создать**: все файлы и привязки загрузятся
   автоматически. По готовности открой полученные ссылки и нажми «Добавить».

По умолчанию используется `exports/blue-pack.zip`. Другой архив того же формата
можно указать в `.env`: `PACK_ARCHIVE=C:/путь/blue-pack.zip`.
Архив должен содержать `tgs/*.tgs` и `manifest.csv` с полями
`file,emoji,bytes,sha256`, как у `scripts/package-blue.py`. Поддерживается 1–50
анимаций в одном архиве. Проверяются хэши, размеры и параметры анимаций.

Владельцем наборов будет твой аккаунт. Telegram требует, чтобы имя ссылки
заканчивалось на `_by_имябота`; суффикс добавляется автоматически. Для режима
«Оба» перед ним также добавляются `_emoji` и `_stickers`. Названия двух наборов
одинаковые; привязки берутся из манифеста, включая составные эмодзи.
Синий цвет сохраняется: адаптивная перекраска не включается.

`/newpack` начинает создание, `/status` показывает прогресс,
`/cancel` отменяет настройку до начала загрузки. Ctrl+C останавливает процесс.
Прогресс показывает каждый текущий файл. Если Telegram отвечает лимитом 429,
`/status` и консоль показывают ожидание с учётом `retry_after`; оно может длиться
несколько минут. Бот ждёт положенное время, не повторяя запросы раньше срока.
После ошибки нажми «Создать» ещё раз с теми же настройками. После перезапуска
повтори `/newpack` с прежним типом, названием и ссылкой: файлы берутся из кэша,
уже созданные наборы повторно не создаются. В режиме «Оба» готовая ссылка
отправляется сразу, поэтому при ошибке второго набора первый остаётся доступным.

Токен хранится в локальном `.env`, привязка владельца и кэш — в
`exports/telegram-bot/<id-бота>.json`; оба пути исключены из Git. Не удаляй кэш,
если нужно продолжить прерванную публикацию. Для запуска используй отдельного
бота без webhook; существующий webhook скрипт не меняет.

Автоматическое добавление набора в установленный список аккаунта Bot API не
предоставляет: последний шаг «Добавить» выполняется по ссылке в Telegram.
Использование пользовательских эмодзи регулируется условиями Telegram Premium.

Справка: [создание набора и ограничения ссылок](https://core.telegram.org/bots/api#createnewstickerset),
[формат привязок](https://core.telegram.org/bots/api#inputsticker),
[эмодзи и Premium](https://core.telegram.org/stickers#custom-emoji).

## Управление из редактора

Если в `.env` есть `BOT_CONTROL_TOKEN`, V2 поднимает HTTP-сервер только на `127.0.0.1:BOT_CONTROL_PORT`
(по умолчанию 8790), запросы — с заголовком `Authorization: Bearer <ключ>`:
`GET /sets` — наборы владельца, `GET /status` — текущая задача, `POST /append {"names": [набор, …], "files": ["x.tgs", …]}`
(или `"name"`) — добавить только эти файлы, по порядку, в каждый набор по очереди (без `files` — всё
отсутствующее, как `/add` в чате); прогресс — одним сообщением в чат владельцу. С `files` бот после каждого
набора присылает эти файлы так, как они лежат в наборе: находит их по байтам (`Publisher.placed`) и шлёт `sendSticker`.
Пока идёт загрузка, второй запуск отклоняется (409). Им пользуется кнопка «В Telegram» — см. `docs/remote.md`.

## Как бот узнаёт, что стикер уже в наборе (исправлено 2026-10-22)

Стикер в наборе получает в Telegram другие `file_id` и `file_unique_id`, чем файл при загрузке, поэтому сверка
по id никогда не срабатывала: дозагрузка считала набор пустым и отправляла весь архив. Telegram хранит TGS без
изменений, поэтому теперь бот берёт `getStickerSet` (один запрос), у стикеров того же размера, что добавляемые
файлы, один раз скачивает файл и сравнивает SHA-256; хэши запоминаются (`set_hashes` в кэше бота) и повторно
не скачиваются. Кнопка «В Telegram» передаёт боту только выбранный файл.
