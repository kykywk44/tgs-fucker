# Работа с телефона

`scripts/start-remote.cmd` (или `node scripts/remote.mjs`) запускает одним процессом:

- редактор — Vite на `127.0.0.1:5173`;
- бота V2 — `scripts/telegram-pack-bot-v2.py` с локальным управлением для кнопки «В Telegram»;
- быстрый Cloudflare-туннель к редактору.

Адрес `https://….trycloudflare.com` печатается в консоли и пишется в `exports/remote-url.txt`; он меняется
при каждом запуске (постоянный адрес — только именованный туннель на своём домене). Ctrl+C останавливает всё.
`--no-bot` — без бота.

## Пароль

`server/remote.ts` (плагин Vite): всё, что пришло через туннель, требует входа на `/__login` с паролем
`SITE_PASSWORD` из `.env`; cookie живёт 30 дней, выход — `/__logout`. Пять неверных попыток с одного адреса —
блок на 15 минут. Запросы с самого компьютера (без заголовков прокси, с loopback-адреса) идут без пароля,
поэтому `localhost:5173` работает как раньше. Нет `SITE_PASSWORD` — через туннель не пускает никого.
WebSocket горячей перезагрузки проверяется так же. Vite и сам не отдаёт файлы вне проекта и `.env`.

## «В Telegram»

Вкладка «Эмодзи» → «Синий пак · черновики» или «готово» → выбрать один или несколько стикеров (порядок
кликов — порядок добавления) → «В Telegram». Или открыть стикер оттуда в редакторе → «Добавить в пак» в
инспекторе. В панели: эмодзи-привязка каждого (подставляется из `packs/blue/emoji.txt` или `recipe.json`) и
галочки наборов бота — можно несколько, они обходятся по очереди. «Добавить»:

1. все проверяются заранее; стикер, у которого в `packs/blue/ready/` другая версия, пропускается (замена
   элемента в наборе пока не поддерживается, бот добавил бы его вторым);
2. черновики копируются в `packs/blue/ready/`, привязки дописываются в `packs/blue/emoji.txt` в этом порядке;
3. `scripts/package-blue.py` один раз пересобирает `exports/blue-pack.zip` (ошибка — копии и привязки откатываются);
4. бот получает `POST /append {"names": [...], "files": [...]}` на `127.0.0.1:BOT_CONTROL_PORT` с ключом
   `BOT_CONTROL_TOKEN` и добавляет эти файлы по порядку в каждый набор по очереди (что уже есть — пропускает);
   прогресс — в чате с ботом и в панели; потом бот присылает в чат каждый стикер/эмодзи из каждого набора,
   как он там получился (`sendSticker` с файлом из набора);
5. индекс библиотеки пересобирается в фоне; «Готово» в библиотеке идёт от новых к старым (обратный порядок
   `emoji.txt`).

Запуск очереди сразу подтверждается сайту; отправка сообщения прогресса идёт в отдельном потоке.
Если Telegram не ответил на `sendMessage`, загрузка продолжается, а статус виден в панели сайта
и по `/status`. Неопределённый результат отправки сообщения автоматически не повторяется,
чтобы не создавать дубликаты. При сетевом сбое самой загрузки готовые файлы и кэш сохраняются;
повторная отправка сверяет содержимое пака и пропускает уже добавленное.
После обновления Python-кода нужен перезапуск бота пользователем; работающий процесс сам не обновляется.

API: `server/remote.ts` (шапка файла). Телефонная вёрстка: на узком экране кнопки шапки — значками,
«Образцы» скрыты, холст подстраивается под ширину, «Открыть» в нижней панели заменяет двойной клик.
